## Setup commands

```bash
# From repo root:
mkdir -p web && cd web
npx create-next-app@latest . --typescript --tailwind --eslint --app --src-dir=false --import-alias "@/*"
# Accept defaults; we'll customize.

# shadcn
npx shadcn@latest init
# Style: default
# Base color: slate
# CSS vars: yes

# Initial components
npx shadcn@latest add button card input textarea label badge separator dialog scroll-area tooltip sonner

# Optional but useful:
npx shadcn@latest add tabs accordion
```

import { z } from "zod";

const envSchema = z.object({
  NEXT_PUBLIC_API_BASE: z.string().url().default("http://localhost:8000"),

## Vercel deploy

1. Connect the GitHub repo to a Vercel project.
2. Set Root Directory: `web`.
3. Build command: `npm run build`.
4. Output: `.next` (default).
5. Env vars in Vercel project settings:
   - `NEXT_PUBLIC_API_BASE` — production VX1 URL after S4 (`https://govcapture.example.com`).
   - For preview deployments, point at a stable dev API URL or use the mock.

Every push to a feature branch auto-deploys a preview URL. Use those for review.

## Pitfalls

- **shadcn version drift.** Don't mix `shadcn@latest` (CLI) versions across devs. Pin in `components.json`.
- **Forgetting `--src-dir=false`.** We use `app/` not `src/app/` to keep paths short. If you accidentally chose src-dir, restart.
- **Env vars at build time.** `NEXT_PUBLIC_*` is the only kind that's exposed to the client. Server-only secrets (none in this app for v1) would use server components.
- **Vercel cache.** If a generated schema isn't committed and you build on Vercel, the build fails. Always commit `/web/lib/schemas/`.
- **CORS during dev.** If you're hitting the API on `localhost:8000` from `localhost:3000`, the API needs `CORSMiddleware` allowing both. Coordinate with A.
