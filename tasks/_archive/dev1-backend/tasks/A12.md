## What gets asserted

For each fixture, `expected.json` declares assertions. The runner loads it and runs the equivalent of:

```python
def assert_fixture(slug, actual_run_output, expected):
    # Extraction
    if "extracted_requirements" in expected:
        e = expected["extracted_requirements"]
        actual_titles = {r["title"].lower() for r in actual_run_output["requirements"]}
        for required in e.get("required_titles", []):
            assert any(required.lower() in t for t in actual_titles), \
                f"missing required title: {required}"

        if "min_count" in e:
            assert len(actual_run_output["requirements"]) >= e["min_count"]

        if e.get("evidence_required_for_confidence"):
            for r in actual_run_output["requirements"]:
                if r["confidence"] in e["evidence_required_for_confidence"]:
                    assert r["evidence_snippet"], f"{r['title']} missing evidence_snippet"
                    assert r["page_number"] is not None, f"{r['title']} missing page_number"

    # Fit score
    if "fit_score" in expected:
        f = expected["fit_score"]
        actual = actual_run_output["fit_score"]
        if "decision" in f:
            assert actual["decision"] == f["decision"], \
                f"decision mismatch: expected {f['decision']}, got {actual['decision']}"
        if "min_total" in f:
            assert actual["total_score"] >= f["min_total"]
        if "max_total" in f:
            assert actual["total_score"] <= f["max_total"]
        if f.get("must_not_have_critical_blockers"):
            assert not actual.get("blockers"), f"unexpected blockers: {actual['blockers']}"
        if f.get("must_have_critical_blocker"):
            assert actual.get("blockers"), "expected critical blocker, none present"
        if f.get("eligibility_score_must_be_zero"):
            assert actual["score_breakdown"]["eligibility"] == 0

    # Risks
    if "risks" in expected:
        # critical_count, expected_categories
        ...

    # Action package
    if "action_package" in expected:
        # all_sections_present, partner_suggestions_count, etc.
        ...

    # Adversarial
    if "parse_pdf" in expected and expected["parse_pdf"].get("must_return_unparseable"):
        assert actual_run_output["parse_pdf"]["unparseable"] is True

    if "agent_run" in expected and expected["agent_run"].get("must_not_crash"):
        # already passed if we reached this point
        pass
```

## §11.1 special assertion (mandatory)

The reject fixture's `expected.json` includes:

```json
{
  "fit_score": {
    "decision": "reject",
    "must_have_critical_blocker": true,
    "eligibility_score_must_be_zero": true
  },
  "_eligibility_short_circuit_assertion": {
    "description": "Capability strength must NOT override the reject decision",
    "capability_score_min": 15,
    "decision_must_be": "reject"
  }
}
```

The runner has dedicated logic:

```python
if "_eligibility_short_circuit_assertion" in expected:
    sc = expected["_eligibility_short_circuit_assertion"]
    assert actual["fit_score"]["score_breakdown"]["capability"] >= sc["capability_score_min"], \
        "test setup invalid: capability must be high to validate the override-prevention rule"
    assert actual["fit_score"]["decision"] == sc["decision_must_be"], \
        f"§11.1 violation: capability strong but decision={actual['fit_score']['decision']}"
```

**This assertion catches PRD §11.1 regressions in CI.** If a future prompt change weakens the deterministic short-circuit in A6 or A8, this fails. Belt + suspenders.

## Cost cap

The full `make eval` should run under $0.10. Tracked by `pricing.py` watching skill-emitted `cost_usd`. If a single eval exceeds $0.20, abort with a warning.

This forces prompts to stay efficient — no expensive Sonnet calls in the eval path unless necessary. Use Haiku for extraction/risks during eval; Sonnet only for the strong-pursue action package.

## Pitfalls

- **Goldens drift faster than you expect.** When prompts change, goldens shift too. Use `--update-goldens` (with care) to regenerate; review the diff before committing.
- **Network/model variance.** LLM calls with low temperature still vary. Don't pin exact strings — assert structure, presence of keywords, and decision bands.
- **Eval too slow.** If a fixture takes > 30s, drop a tool from the eval path (e.g., skip detect_risks for fixtures where it's not asserted on).
- **Skipping the §11.1 assertion in dev.** Always run it. It's the most important guardrail in the system.
