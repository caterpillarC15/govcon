>
> 1. **Skill location:** `api/skills/extract_requirements/{__init__.py, skill.py, prompt.txt}` instead of `api/agent/tools/extract_requirements.py`. Same reason as A4 — stable user-facing path through A9.

Eliminates the "model returned markdown-fenced JSON / missing field / extra field" failure modes that the spec's retry loop was working around. On unrecoverable error we still return the spec's degraded output (empty requirements, `missing_fields=["all"]`) so the planner's recovery branch (PRD §4.5) can take over.

> 4. **Output-shape Pydantic lives in the skill module** (`ExtractedRequirementLLM`, `RequirementExtractionOutput`, `RequirementConflict`) rather than in `/api/schemas/` — this is the LLM intermediate shape, not the persisted entity. The persisted entity (`ExtractedRequirement`, with `id` / `opportunity_id` / `created_at`) lives in `/schemas/extracted-requirement.schema.json` and the repository layer maps between them.

> **Post-validation (PRD §11) all in place:** out-of-range `page_number` → null + downgrade to `low`; `confidence ∈ {high, medium}` without `evidence_snippet` → downgrade; `evidence_snippet` that doesn't substring-match or fuzzy-match (`SequenceMatcher` ratio ≥ 0.3, lenient because pypdf reorders columns) any chunk → downgrade. > **Live LLM verification deferred** until `.env` has a real `ANTHROPIC_API_KEY`. Skill imports cleanly and is wired through `api/llm.py`; A9 picks it up as a Hermes toolset.

## Output schema (PRD §10.1)

```python
class ExtractedRequirement(BaseModel):
    type: Literal["eligibility", "technical", "past_performance", "certification",
                  "insurance", "bonding", "security", "submission", "evaluation",
                  "deadline", "location", "pricing", "document_required"]
    title: str
    value: str
    description: str
    confidence: Literal["high", "medium", "low", "unknown"]
    evidence_snippet: str
    source_document: str
    page_number: int | None
    is_blocker: bool


class RequirementConflict(BaseModel):
    field: str
    candidates: list[str]
    requires_human_review: bool


class RequirementExtractionOutput(BaseModel):
    requirements: list[ExtractedRequirement]
    missing_fields: list[str]
    conflicts: list[RequirementConflict]
```

## Hard rules (enforced in code, not just prompt)

After the LLM returns, validate:

1. **Schema-valid JSON.** Reject and retry if parsing fails or fields are missing.
2. **Evidence binding.** Every requirement with `confidence ∈ {high, medium}` MUST have a non-empty `evidence_snippet`. Reject and retry if missing.
3. **Page numbers** must reference real pages from the parsed input (1 ≤ page_number ≤ page_count). Reject if out of bounds.
4. **No fabrication.** `evidence_snippet` should appear (loosely) in the source text. Use a fuzzy match (e.g., `difflib.SequenceMatcher.ratio() > 0.6`); if the snippet isn't present in any chunk, downgrade the confidence to `low` and flag.

These post-validation steps are CHEAP and catch ~80% of hallucinations.

## Skeleton

```python
import json
import logging
from pathlib import Path
from anthropic import AsyncAnthropic
from pydantic import ValidationError

from api.agent.tools.parse_pdf import ParsedPdf
from api.config import settings
from api.schemas.extracted_requirement import RequirementExtractionOutput


PROMPT_PATH = Path(__file__).parent.parent / "prompts" / "extract_requirements.txt"
PROMPT_TEMPLATE = PROMPT_PATH.read_text()
logger = logging.getLogger(__name__)


async def extract_requirements(
    parsed: ParsedPdf,
    opportunity_metadata: dict,
    *,
    model: str | None = None,
    client: AsyncAnthropic | None = None,
) -> tuple[RequirementExtractionOutput, dict]:
    """Returns (output, metrics) where metrics has latency_ms and cost_usd."""
    if parsed.unparseable:
        return (
            RequirementExtractionOutput(requirements=[], missing_fields=["all"], conflicts=[]),
            {"latency_ms": 0, "cost_usd": 0.0, "skipped_reason": "unparseable"},
        )

    client = client or AsyncAnthropic(api_key=settings.anthropic_api_key)
    model = model or settings.llm_dev_model

    chunks_text = "\n\n".join(
        f"[page {c.page_number}]\n{c.text}" for c in parsed.chunks
    )
    prompt = PROMPT_TEMPLATE.format(
        opportunity_metadata=json.dumps(opportunity_metadata, indent=2),
        chunks=chunks_text,
        doc_id=parsed.doc_id,
    )

    output, metrics = await _call_with_retry(client, model, prompt, parsed)
    output = _post_validate(output, parsed)
    return output, metrics


async def _call_with_retry(client, model, prompt, parsed):
    import time
    t0 = time.monotonic()
    last_error = None

    for attempt in range(2):
        msg = await client.messages.create(
            model=model,
            max_tokens=4000,
            system="You return only valid JSON matching the provided schema.",
            messages=[{"role": "user", "content": prompt + (
                "\n\nYour previous response was invalid. Return ONLY valid JSON matching the schema. No prose."
                if attempt > 0 else ""
            )}],
        )
        raw = msg.content[0].text
        cost = _estimate_cost(model, msg.usage.input_tokens, msg.usage.output_tokens)
        try:
            data = json.loads(raw)
            output = RequirementExtractionOutput.model_validate(data)
            return output, {
                "latency_ms": int((time.monotonic() - t0) * 1000),
                "cost_usd": cost,
                "attempts": attempt + 1,
            }
        except (json.JSONDecodeError, ValidationError) as e:
            last_error = e
            logger.warning("extract_requirements invalid JSON, attempt=%d, err=%s", attempt, e)
            continue

    # Final fallback: return degraded output, mark for human review
    logger.error("extract_requirements failed twice on %s: %s", parsed.doc_id, last_error)
    return (
        RequirementExtractionOutput(requirements=[], missing_fields=["all"], conflicts=[]),
        {"latency_ms": int((time.monotonic() - t0) * 1000), "cost_usd": 0.0, "failed": True},
    )


def _post_validate(output: RequirementExtractionOutput, parsed: ParsedPdf) -> RequirementExtractionOutput:
    """Post-LLM validation: evidence binding, page-number bounds, fuzzy snippet check."""
    from difflib import SequenceMatcher

    page_texts = {c.page_number: c.text for c in parsed.chunks}
    cleaned: list = []
    for req in output.requirements:
        # Page bounds
        if req.page_number is not None and req.page_number not in page_texts:
            req = req.model_copy(update={"page_number": None, "confidence": "low"})

        # Evidence required for medium/high
        if req.confidence in ("high", "medium") and not req.evidence_snippet.strip():
            req = req.model_copy(update={"confidence": "low"})

        # Fuzzy snippet match
        if req.evidence_snippet and req.page_number is not None:
            page_text = page_texts.get(req.page_number, "")
            ratio = SequenceMatcher(None, req.evidence_snippet[:200], page_text).ratio()
            if ratio < 0.3 and req.confidence in ("high", "medium"):
                req = req.model_copy(update={"confidence": "low"})

        cleaned.append(req)

    return output.model_copy(update={"requirements": cleaned})


def _estimate_cost(model: str, in_tokens: int, out_tokens: int) -> float:
    # Approximate per-million-token rates; adjust to current pricing.
    rates = {
        "claude-haiku-4-5-20251001": (1.0, 5.0),
        "claude-sonnet-4-6": (3.0, 15.0),
    }
    in_rate, out_rate = rates.get(model, (3.0, 15.0))
    return (in_tokens * in_rate + out_tokens * out_rate) / 1_000_000
```

## Per-requirement-type prompting (PRD §17 risk)

The single mega-prompt approach works for v1 but risks misses on long solicitations. If eval shows < 80% recovery on any fixture, switch to per-type prompting:

- Pass 1: eligibility / set-aside / certification / clearance (highest stakes)
- Pass 2: technical / past_performance / submission / evaluation
- Pass 3: deadline / location / pricing / insurance / bonding / document_required

Merge results with deduplication by `(type, title)`.

For v1 with 1–2 page fixtures, the single-prompt approach is sufficient. Don't pre-optimize.

## Pitfalls

- **Hallucinated evidence snippets.** Most common failure. Mitigate with fuzzy match; consider fully gating medium+ confidence on snippet-found-in-source.
- **Page numbers off by one.** PDF page numbering can disagree with the printed page numbers. Use `page_number` from `pypdf` (1-indexed) consistently.
- **Haiku produces shallower extractions.** For dev iteration with Haiku, accept lower recall; for the eval, run with Sonnet.
- **JSON wrapped in markdown code fences.** Some models return ` ```json ... ``` ` — strip these before `json.loads`. Use a tolerant parser.
- **Conflicts under-reported.** The model rarely flags conflicts; that's OK — `conflicts` is a stretch field. Don't over-engineer.
