## Planner instructions

Hermes' planner needs domain context. Write a system-prompt-style instruction document the run is initialized with:

```text
You are a federal-contract capture analyst working on behalf of a small business.

Goal: <user's contracting goal>
Profile: <serialized CompanyProfile>

Available skills:
- search_sam_opportunities, load_seeded_opportunities: get candidate opportunities
- parse_pdf: extract text from solicitation attachments
- extract_requirements: turn parsed text into structured requirements
- score_fit: apply the §5.7 rubric; outputs a decision band
- detect_risks: flag PRD §5.8 risk categories
- generate_action_package: produce the final deliverable per §10.3

Hard rules:
1. PRD §11.1 — eligibility uncertainty is always a critical blocker. score_fit enforces this; if it returns decision=reject, do NOT generate a full action plan. Call generate_action_package once for the slim reject summary and stop on that opportunity.
2. Every requirement with confidence ≥ medium MUST have an evidence_snippet. extract_requirements enforces this; surface any missing-evidence cases as needs_human.
3. Budget: max 40 steps, 6 minutes wall-clock, $0.50 LLM cost per run. Score the top 3 ranked opportunities deeply; summarize the rest if budget remains.
4. Prefer cached/seeded opportunities when search rate-limits or fails. The fallback skill is load_seeded_opportunities.
5. Do not invent data. Source-bind every claim.

Workflow:
1. Search or load opportunities (matching goal keywords, NAICS, set-aside).
2. For each top-N opportunity:
   a. parse_pdf on attachments
   b. extract_requirements
   c. score_fit (this enforces §11.1)
   d. detect_risks
   e. generate_action_package
3. Return the ranked list and selected action package.

Emit one-sentence rationales for each tool call. The frontend renders these.
```

This is loaded once per run via `planner_instructions.build(profile, goal)`.

## The trace bridge

This is the critical piece. Hermes emits trace events in its own format; the frontend (B5) consumes our CONTRACTS.md §3 events. Translate.

```python
import json
from uuid import UUID
from api.agent.hermes_runner import hermes_run
from api.redis import redis_client


CHANNEL = "agent-run:{run_id}"


async def run_and_bridge(run_id: UUID, profile: CompanyProfile, goal: str) -> None:
    await emit("run_started", run_id, goal=goal, profile_id=str(profile.id))

    async for hermes_event in hermes_run(
        instructions=build_planner_instructions(profile, goal),
        skills=DOMAIN_SKILLS,
        budget={
            "max_steps": settings.run_budget_steps,
            "max_seconds": settings.run_budget_seconds,
        },
    ):
        translated = translate(hermes_event, run_id)
        if translated is None:
            continue
        await emit(translated["type"], run_id, **translated["payload"])

    await emit("run_completed", run_id, status="complete", summary=...)


def translate(hermes_event: dict, run_id: UUID) -> dict | None:
    """Map Hermes' trace event types to CONTRACTS.md §3 union members."""
    kind = hermes_event.get("kind")
    match kind:
        case "step_start":
            return {"type": "step_started", "payload": {
                "step_id": hermes_event["step_id"],
                "label": hermes_event.get("label", "Working"),
                "ts": hermes_event["ts"],
            }}
        case "tool_call":
            return {"type": "tool_called", "payload": {
                "step_id": hermes_event["step_id"],
                "tool": hermes_event["tool"],
                "input": hermes_event["input"],
                "rationale": hermes_event.get("rationale", ""),
                "ts": hermes_event["ts"],
            }}
        case "tool_result":
            return {"type": "tool_returned", "payload": {
                "step_id": hermes_event["step_id"],
                "tool": hermes_event["tool"],
                "output": hermes_event.get("output"),
                "error": hermes_event.get("error"),
                "latency_ms": hermes_event["latency_ms"],
                "cost_usd": hermes_event.get("cost_usd", 0.0),
                "ts": hermes_event["ts"],
            }}
        case "step_end":
            return {"type": "step_completed", "payload": {
                "step_id": hermes_event["step_id"],
                "status": hermes_event["status"],  # complete | degraded | failed | needs_review
                "ts": hermes_event["ts"],
            }}
        case "internal" | "memory_write" | "planner_thought":
            return None  # filter Hermes-internal events the frontend doesn't render
        case _:
            # Unknown event — log but don't break the stream
            logger.warning("unmapped hermes event kind: %s", kind)
            return None


async def emit(event_type: str, run_id: UUID, **payload):
    event = {"type": event_type, "run_id": str(run_id), "ts": now_iso(), **payload}
    await redis_client.publish(CHANNEL.format(run_id=run_id), json.dumps(event))
```

Some events the planner emits directly (not from Hermes), based on tool returns:

- `opportunity_ranked` — emitted after each `score_fit` returns; payload `{opportunity_id, score, decision}`.
- `needs_human` — emitted when a skill raises a needs-review error or when budget exhausts mid-opportunity.

These live in the bridge's post-processing of `tool_returned` events.

## Hermes invocation: subprocess vs. SDK

Hermes is primarily a CLI tool. Two integration options:

1. **Subprocess.** `subprocess.Popen(["hermes", "run", "--instructions", path, "--skills", ...])` and stream stdout JSONL. Simple, but trace shape depends on Hermes' output format being stable.
2. **Python SDK** (if Hermes exposes one as it matures). `from hermes_agent import HermesClient`.

For the hackathon, **start with subprocess** unless an obvious SDK exists. Wrap behind `hermes_runner.py` so the rest of the codebase doesn't care.

## §11.1 enforcement under Hermes

The eligibility rule is enforced in three places:

1. **`score_fit` skill** (A6) — deterministic short-circuit before rubric math.
2. **`generate_action_package` skill** (A8) — slimmed reject package returned without LLM call.
3. **Planner instructions** (above) — explicit rule "if score_fit returns decision=reject, don't generate full plan."
4. **Eval harness** (A12) — assertion that capability strengths cannot override the reject fixture.

Belt + suspenders + parachute. Hermes' general-purpose planner doesn't know about our rule on its own; we tell it.

## Budget control

Hermes supports `max_steps` and `max_seconds`. Our $0.50 cost cap is tracked separately by summing `cost_usd` from skill returns (LLM-backed skills compute this from token counts).

```python
class BudgetTracker:
    def __init__(self):
        self.usd_used = 0.0

    def consume(self, hermes_event):
        if hermes_event.get("kind") == "tool_result":
            self.usd_used += hermes_event.get("cost_usd", 0.0)

    def exhausted(self) -> bool:
        return self.usd_used >= settings.run_budget_usd
```

If the cost cap is hit, signal Hermes to halt (mechanism depends on Hermes' API — graceful interrupt or kill the subprocess and emit a partial `run_completed`).

## Pitfalls

- **Trace bridge silently drops events.** Hermes will emit kinds we haven't mapped. The `case _:` branch logs them; check logs after the first run to discover any we should handle.
- **Subprocess deadlocks.** If Hermes blocks on stdin or fills its pipe, the API hangs. Use unbuffered output and read stdout in a separate task.
- **§11.1 not enforced because the planner ignored the instruction.** That's why we have it deterministic in `score_fit` AND `generate_action_package`. Don't rely solely on the planner-instruction rule.
- **Hermes auto-creates new skills mid-run.** Cool feature, but we don't want it inventing skills that bypass our domain logic. Configure Hermes to use only the registered skill list (no skill creation in v1).
- **Cost runaway from Hermes' planner deliberation.** Hermes' planner itself uses an LLM. Track that cost too — it's not in our skill returns. May need to wrap Hermes' planner-LLM call to count tokens.
