# A13 — VX1 deploy: bootstrap, nginx, TLS, Hermes, Supabase wiring (v1.2.3)

**Goal:** PRD §7.6 (v1.2.3) production deployment on the Vultr VX1 box. Single command from a fresh Ubuntu 24.04 LTS image to a working HTTPS-served stack with Redis (SSE pub/sub) + FastAPI under systemd + Hermes (subprocess) + nginx + TLS — connected to Supabase Postgres + Storage. **Sync checkpoint S4.**

**PRD references:** §7.5, §7.6, §13.1 (`DEMO_USE_SEEDED_ONLY`).
**Depends on:** A1, A3, A9, A12.
**Blocks:** S4, S5.

> **No Docker.** Per the 2026-05-09 decision, the VX1 runs Redis, FastAPI, nginx, and Hermes (subprocess of FastAPI) as native systemd services. No Dockerfile, no compose. **Postgres lives in Supabase** (PRD v1.2.3) — no on-box pg, no pg_dump cron, no `/var/lib/govcapture` data dir.

> **What changed from v1.2.2:** the `postgresql-16` install + role/db setup, the `/var/lib/govcapture/{raw,parsed}` working dirs, the `govcapture-backup.{service,timer}` units, and `infra/backup.sh` are gone. Bootstrap shrinks from 9 steps to 7. Operators now create a Supabase project and drop its connection string + service-role key into `.env` before starting the API.

## Operator setup checklist

### 1. Supabase project (one time, before bootstrap)

1. https://supabase.com → New project. Region close to VX1.
2. **Settings → Database → Connection string → Direct connection** (port `5432`). Capture the URL — replace `[YOUR-PASSWORD]` with the password you set.
3. **Settings → API** — capture `URL`, `anon public` key, `service_role` key.
4. **Storage → New bucket** → `govcapture-attachments` (private, no public read).
5. (Optional, recommended) Storage → Policies — add a 30-day retention rule on the `raw/` prefix per PRD §17 Q6.

> **Direct Connection URL only** (port 5432). The pgBouncer pooler at 6543 runs in transaction mode and rejects asyncpg's prepared statements.

### 2. VX1 bootstrap (idempotent)

```bash
ssh root@<box-ip>
git clone https://github.com/caterpillarC15/govcon.git /tmp/govcon
sudo bash /tmp/govcon/infra/bootstrap.sh
```

Installs apt packages (Python, Redis, nginx, certbot, ufw, fail2ban, build tools), enables unattended-upgrades, configures the firewall (22/80/443), creates the `govcapture` user + `/opt/govcapture` working dir, installs `uv`, enables Redis, installs the API systemd unit. **No Postgres.**

### 3. Drop the prod `.env`

```bash
sudo -u govcapture install -m 0600 /dev/null /opt/govcapture/.env
sudo -u govcapture editor /opt/govcapture/.env
```

Required:
- `DATABASE_URL` — Supabase Direct Connection URL (port 5432, with password substituted in).
- `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`, `SUPABASE_STORAGE_BUCKET`.
- `ANTHROPIC_API_KEY`.
- `REDIS_URL=redis://localhost:6379/0` (default).
- `HERMES_HOME=/var/lib/hermes` (mode 0700, owned by `govcapture`).

### 4. Sync deps + migrate Supabase + start

From a machine with the repo **linked** to Supabase (`supabase link`):

```bash
cd /path/to/govcon && supabase db push
```

On the VX1:

```bash
sudo -u govcapture -H bash -lc 'cd /opt/govcapture && ~/.local/bin/uv sync'
sudo systemctl enable --now govcapture-api.service
curl http://127.0.0.1:8000/healthz
```

DDL lives in `supabase/migrations/`. The FastAPI engine adds `ssl=require` for non-localhost `DATABASE_URL` hosts.

### 5. Wire nginx + TLS

```bash
sudo cp /opt/govcapture/infra/nginx/govcapture.conf /etc/nginx/sites-available/
sudo sed -i 's|api.your-domain.example|api.govcapture.example|g' \
  /etc/nginx/sites-available/govcapture.conf
sudo ln -sf /etc/nginx/sites-available/govcapture.conf /etc/nginx/sites-enabled/
sudo rm -f /etc/nginx/sites-enabled/default
sudo nginx -t && sudo systemctl reload nginx
sudo certbot --nginx -d api.govcapture.example --redirect --agree-tos -m you@example.com -n
```

## Hermes prod config

- `hermes model` set to `claude-sonnet-4-6` for synthesis path.
- `HERMES_HOME=/var/lib/hermes` (mode 0700, owned by `govcapture`) — survives `redeploy.sh` because it lives outside `/opt/govcapture`.
- Hermes' skill-creation feature is OFF by default for this deployment (we want the registered skill set, no surprises).
- Hermes' execution backend is **local subprocess only** — no Docker, no SSH, no Modal. Configured in `~govcapture/.hermes/config.yaml`.
- LLM API key flows through Hermes via `ANTHROPIC_API_KEY` in `/opt/govcapture/.env`.

## Pitfalls

- **pgBouncer pooler vs direct.** `DATABASE_URL` MUST point at port 5432 (Direct Connection). Port 6543 (pooler, transaction mode) fails with `prepared statement does not exist` on every other request.
- **Service role key leaks.** `SUPABASE_SERVICE_ROLE_KEY` MUST stay server-side. Don't bake it into Vercel env or any Next.js client bundle. The frontend uses `SUPABASE_ANON_KEY` only; for v1.2.3 there's no direct browser→Supabase wiring needed (FastAPI mediates).
- **nginx buffering for SSE.** `proxy_buffering off` is non-negotiable on the stream endpoint. Without it the frontend timeline appears frozen until the run completes.
- **Certbot timing.** First-cert acquisition fails if DNS isn't propagated. Either wait or use DNS-challenge.
- **systemd `EnvironmentFile`.** Lines must be `KEY=value` (no `export`, no shell expansion). A misformatted file causes the unit to silently start with empty env. `systemctl show govcapture-api -p Environment` to verify.
- **`uv` PATH for systemd.** systemd doesn't source `~/.bashrc`. Use the absolute path `/home/govcapture/.local/bin/uv` in `ExecStart`.
- **Hermes memory directory.** Without a persistent `HERMES_HOME`, every restart wipes Hermes' state. Demo will start cold; usually fine, but be aware.
- **Migrations on redeploy.** Run `supabase db push` when `supabase/migrations/` changed, **before** restarting the API. `deploy.sh` does not apply DDL.
- **Supabase outage.** Unlike v1.2.2 (single-box), a Supabase outage now kills the demo. Mitigation: pre-cache an entire successful run for the demo backup path (PRD §13.1 already calls this out under "Backup demo paths").
