# A8 — `generate_action_package` LLM tool

**Goal:** Synthesize the full PRD §10.3 action package — the deliverable artifact. Sonnet only. Every section non-empty for pursue decisions; reject decisions get a slimmed-down package.

**PRD references:** §5.11, §5.13, §10.3.
**Depends on:** A5, A6, A7.
**Blocks:** A9, A12.

---

## Output schema (PRD §10.3)

See `/schemas/action-package.schema.json`. Required sections:

1. `executive_summary` (string, ~3 sentences)
2. `decision` (string)
3. `fit_score` (int)
4. `fit_rationale` (string, ~2 paragraphs)
5. `compliance_matrix` (array of `{requirement, status, evidence, next_action, owner}`)
6. `risk_register` (array of `{risk, severity, explanation, mitigation}`)
7. `proposal_checklist` (array of strings — concrete TODOs)
8. `timeline` (array of `{date, task, owner}`)
9. `partner_suggestions` (array, possibly empty)
10. `outreach_draft` (`{subject, body}`)
11. `human_approval_required` (array of strings — what requires approval)

## Behavior by decision band

| Decision | What the package contains |
|----------|---------------------------|
| `strong_pursue` / `pursue` | All 11 sections, full proposal checklist, timeline, outreach draft |
| `maybe` | All sections, but proposal checklist focuses on resolving the blocker first; partner_suggestions populated |
| `reject` | Only sections 1–6 + `human_approval_required`. No proposal checklist, no timeline, no outreach. Decision = reject is final; we don't generate prep work for opportunities we're walking away from. |

This per-band behavior is enforced in the tool, not just the prompt:

```python
async def generate_action_package(
    profile: CompanyProfile,
    opportunity: Opportunity,
    requirements: list[ExtractedRequirement],
    fit_score: FitScoreOutput,
    risks: list[RiskFlag],
) -> tuple[ActionPackageOutput, dict]:
    # Always Sonnet
    model = settings.llm_synth_model

    if fit_score.decision == "reject":
        return _generate_reject_package(profile, opportunity, fit_score, risks), {...}

    return await _generate_full_package(profile, opportunity, requirements, fit_score, risks, model)


def _generate_reject_package(profile, opportunity, fit_score, risks) -> ActionPackageOutput:
    """Deterministic reject package — no LLM call needed for the slimmed shape."""
    return ActionPackageOutput(
        executive_summary=(
            f"Decision: REJECT — {opportunity.title}. "
            f"Critical blockers prevent pursuit: {'; '.join(fit_score.blockers[:2])}."
        ),
        decision="reject",
        fit_score=fit_score.total_score,
        fit_rationale=(
            "Per §11.1, eligibility uncertainty or hard mismatch forces a reject decision "
            "regardless of capability strengths. See risk register for blockers."
        ),
        compliance_matrix=[
            {"requirement": b, "status": "missing", "evidence": "",
             "next_action": "Do not pursue — blocker cannot be resolved within scope.",
             "owner": "—"}
            for b in fit_score.blockers
        ],
        risk_register=[
            {"risk": r.title, "severity": r.severity, "explanation": r.description, "mitigation": r.mitigation}
            for r in risks if r.severity in ("critical_blocker", "major")
        ],
        proposal_checklist=[],
        timeline=[],
        partner_suggestions=[],
        outreach_draft={"subject": "", "body": ""},
        human_approval_required=[
            "This opportunity is marked REJECT. Do not pursue without overriding the eligibility analysis.",
            "Confirm the eligibility blocker with a contracting officer before any external action.",
        ],
    )
```

## Approval gate (always present)

PRD §5.13 requires `human_approval_required` to be non-empty in EVERY package. Default contents:

```python
APPROVAL_DEFAULTS = [
    "Human approval required before contacting a contracting officer.",
    "Human approval required before sending the outreach draft externally.",
    "Human approval required before claiming compliance or certifications.",
    "Human approval required before submitting any proposal materials.",
]
```

Append decision-specific items (e.g., for `maybe`: "Confirm partner outreach is authorized.").

## Compliance matrix construction

Map each high/medium-confidence requirement from A5 into one matrix row. Status:

- `met` — profile satisfies the requirement (e.g., NAICS match, certification present, insurance level adequate)
- `missing` — clear gap (e.g., clearance not held, certification absent)
- `unclear` — extraction confidence low or profile data ambiguous
- `not_applicable` — requirement doesn't apply to this profile/opportunity combo

Determine status deterministically where possible (matching certifications, NAICS, etc.); use the LLM only for the more ambiguous "unclear" decisions and to fill `next_action` and `owner`.

## Pitfalls

- **Outreach draft hallucinating recipient names.** The prompt MUST say "do not invent recipient names; use a generic salutation like 'Contracting Officer'." PRD §5.12 says don't invent contacts.
- **Compliance status hallucinated.** The LLM will say `met` for things it didn't actually verify. Drive status from deterministic checks where possible.
- **Approval block buried at the bottom.** B's UI displays this prominently. Just ensure it's populated.
- **Generating reject packages with full proposal checklists.** The deterministic split above prevents this. Never lower-case a reject into a "well, maybe with mitigation."
- **Cost.** This is the most expensive call (Sonnet, ~5K input tokens, ~3K output). Plan ~$0.03–0.05 per package. Budget accordingly.
