## Skeleton

```python
from pathlib import Path
import pypdf
from pydantic import BaseModel


class ParsedChunk(BaseModel):
    page_number: int
    text: str
    char_count: int


class ParsedPdf(BaseModel):
    doc_id: str
    page_count: int
    unparseable: bool
    chunks: list[ParsedChunk]


UNPARSEABLE_THRESHOLD_CHARS = 50


def parse_pdf(path: Path, doc_id: str | None = None) -> ParsedPdf:
    doc_id = doc_id or path.stem
    reader = pypdf.PdfReader(str(path))
    page_count = len(reader.pages)
    chunks: list[ParsedChunk] = []

    for page_num, page in enumerate(reader.pages, start=1):
        text = (page.extract_text() or "").strip()
        if not text:
            continue
        chunks.append(ParsedChunk(page_number=page_num, text=text, char_count=len(text)))

    total_chars = sum(c.char_count for c in chunks)
    unparseable = total_chars < UNPARSEABLE_THRESHOLD_CHARS

    return ParsedPdf(
        doc_id=doc_id,
        page_count=page_count,
        unparseable=unparseable,
        chunks=[] if unparseable else chunks,
    )
```

---

## Chunking strategy (v1)

- Chunk by **page** first. One chunk per page.
- If a page exceeds ~3000 tokens (rough estimate: ~12k chars), split into sub-chunks at paragraph boundaries while preserving `page_number`.
- Don't try to be clever about section detection — that's the LLM's job in A5.

For v1, the simple per-page approach works well for 1–2 page solicitations. Sub-chunking only matters for the longer real solicitations (which are out of scope unless we wire SAM live).

## Test cases (`tests/test_parse_pdf.py`)

```python
from pathlib import Path
import pytest

from api.agent.tools.parse_pdf import parse_pdf


FIXTURES = Path(__file__).parent.parent.parent / "fixtures"


def test_strong_pursue_pdf_parses():
    out = parse_pdf(FIXTURES / "strong-pursue/attachments/solicitation.pdf")
    assert not out.unparseable
    assert out.page_count >= 1
    assert sum(c.char_count for c in out.chunks) > 200
    assert all(c.page_number > 0 for c in out.chunks)


def test_adversarial_image_pdf_marked_unparseable():
    out = parse_pdf(FIXTURES / "adversarial-image-pdf/attachments/solicitation.pdf")
    assert out.unparseable
    assert out.chunks == []


def test_template_pdf_parses():
    out = parse_pdf(FIXTURES / "_template/attachments/SAMPLE.pdf")
    assert not out.unparseable
    assert len(out.chunks) >= 1
```

## Pitfalls

- **`pypdf` text extraction is rough.** Some PDFs return text with no spaces between words, or in column-jumbled order. Don't try to fix this in the parser — let the LLM handle it in A5.
- **Encrypted PDFs:** wrap `PdfReader` in a try/except for `pypdf.errors.FileNotDecryptedError`. Mark `unparseable: true` and continue.
- **Fonts that produce empty extracts:** some custom-fonts produce ``-style garbage. Treat any `extract_text()` result that's < 10 chars/page or where >50% chars are non-printable as empty for that page.
- **Don't add OCR.** PRD §17 Q2 explicitly says no. If a fixture is image-only, that's the adversarial case.
- **Don't store the parsed text in the DB yet** — A5 takes the chunks directly. Caching is a follow-up if it's slow (it shouldn't be for 1-2 page fixtures).
