## Behavior

1. LLM call with profile + requirements + scoring breakdown (from A6).
2. Validate output against `RiskFlag[]` schema.
3. **Cross-check with §11.1 blockers from A6:** every blocker A6 produced must appear here as a `critical_blocker` risk. If LLM missed one, append it deterministically before return.
4. **`requires_human_review`** is `true` when the LLM is uncertain (e.g., ambiguous solicitation language) or when severity is `critical_blocker`.

```python
async def detect_risks(
    profile: CompanyProfile,
    requirements: list[ExtractedRequirement],
    fit_score: FitScoreOutput,
    *,
    model: str | None = None,
    client: AsyncAnthropic | None = None,
) -> tuple[list[RiskFlag], dict]:
    # ... call LLM with prompt ...
    risks = _llm_call(...)
    risks = _ensure_blockers_surface_as_critical_risks(risks, fit_score)
    return risks, metrics


def _ensure_blockers_surface_as_critical_risks(risks, fit_score):
    """If A6 found a critical blocker that the LLM didn't surface, add it."""
    surfaced = {r.title.lower() for r in risks if r.severity == "critical_blocker"}
    for blocker in fit_score.blockers:
        if not any(b.lower() in s for s in surfaced for b in [blocker[:30]]):
            risks.append(RiskFlag(
                category="clearance_required_but_unavailable" if "clearance" in blocker.lower()
                         else "set_aside_mismatch" if "set-aside" in blocker.lower()
                         else "certification_gap",
                severity="critical_blocker",
                title=blocker[:120],
                description=blocker,
                evidence=None,
                mitigation="Address the blocker or do not pursue.",
                requires_human_review=True,
            ))
    return risks
```

## Done when

- [ ] Strong-pursue: 0 critical risks; possibly minor/moderate concerns.
- [ ] Maybe: at least one major or moderate risk (past-performance weakness).
- [ ] Reject: at least one `critical_blocker` risk (clearance/set-aside).
- [ ] Every A6 blocker appears here as a `critical_blocker` risk.

## Pitfalls

- **LLM over-flagging.** Models tend to surface every conceivable risk. Cap output at 8 risks; ask the prompt to focus on actionable issues.
- **Severity inflation.** Models default to "major" for things that are "moderate." Keep severity definitions in the prompt explicit.
- **Forgetting cross-check with A6.** If a §11.1 blocker doesn't appear here, judges in eval will flag inconsistency. The deterministic post-merge handles this.
- **Mitigation hallucination.** Mitigations like "obtain clearance" are obvious but the LLM may invent specific government processes. Keep mitigations short and high-level.
