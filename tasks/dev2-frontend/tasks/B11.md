## Critical design choices

- **Capability and NAICS match strongly.** This is on purpose. The §11.1 enforcement is meaningful only if the agent rejects DESPITE strong capability. A weak-capability reject doesn't prove anything.
- **Hard blocker:** "Active Secret clearance required for all key personnel." Demo company has `clearance_status: "none"`.
- **Set-aside compatible** (small business). NOT a set-aside mismatch — the blocker is clearance only. Keeps the §11.1 message clean: clearance alone is enough.

## PDF authoring

The clearance language MUST be unambiguous. Place it on **page 2** so the evidence-snippet → PDF deep link demonstrates verifiability:

> Section L.4 — Personnel Security: All proposed key personnel (Program Manager, Lead Security Engineer, Lead Penetration Tester) shall hold active U.S. Government Secret clearance prior to contract award. Personnel without active clearance will not be eligible to perform on this contract.

Place capability and NAICS language on page 1 so they extract cleanly with high confidence — the §11.1 demonstration depends on capability scoring well while the clearance blocker forces reject.

## Pitfalls

- **Clearance language ambiguous.** "Cleared personnel preferred" doesn't trigger the blocker; "shall hold active Secret clearance" does. Be explicit.
- **Capability language too weak.** If A6's capability score doesn't reach 15+ for this fixture, the §11.1 assertion can't validate the override-prevention. Make capability strong.
- **Decision-locking weakened.** If A6's deterministic short-circuit ever lets capability "soften" the reject, this fixture catches it. The assertion is your guardrail — don't disable it.
