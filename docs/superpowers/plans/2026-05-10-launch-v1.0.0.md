# GovCon Bid Desk v1.0.0 Launch Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Drive the GovCon Bid Desk capability pack from its current "183-tests-green, 53-routes-built, never-deployed" state to a tagged `v1.0.0` running in production at `https://api.<domain>` with `/web` + `/landing` on Vercel, schema reconciled with Supabase, end-to-end orchestration verified against `/root/michealaai`, and an LLM-regression eval gate live.

**Architecture:** Six sequenced phases, each with its own definition-of-done and verification gates. Phases 0–1 are ship-blockers (sync repo + schema; deploy backend). Phase 2 is cross-repo (requires `/root/michealaai` cooperation). Phases 3–5 harden the launch (UI polish + eval gate + production email). Phase 6 cuts the tag.

**Tech Stack:** FastAPI · Python 3.12 · `uv` · Supabase (Postgres + Auth + Storage) · Redis · Anthropic SDK · Next 15 + React 19 + Tailwind 4 · Vultr VX1 (Ubuntu 24.04) · nginx + systemd · Vercel · Resend.

**Authoritative source docs already in repo (do not duplicate; reference instead):**
- `devdocs/HANDOFF_PROMPT.md` — sprint definitions §8–§14
- `devdocs/CURRENT_STATE.md` — verified state §10
- `infra/RUNBOOK.md` — VX1 deploy runbook §§0–11
- `devdocs/CAPABILITY_PACK_INTEGRATION.md` — Sprint G run-pickup contract
- `tasks/LANDING_BRIEF.md` + `devdocs/V1_PRODUCT_ALIGNMENT.md` — copy/voice for Phase 3c

**Conventions used in this plan:**
- `[USER]` = step requires the user (account creation, key procurement, hardware provisioning, cross-repo work). Pause and ask.
- `[ENG]` = step is engineer-executable from this repo.
- `[VERIFY]` = quality gate; do not proceed until green.
- Direct-to-`main` commits are pre-authorized for GovCon work (per project decision log entry 2026-05-10).
