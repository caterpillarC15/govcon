## Codebase conventions you MUST follow (learned the hard way in Phases 0-3)

These caused real subagent escalations during the prior session. Bake them into every prompt you write:

### Skill API pattern
- File layout: `api/skills/<name>/__init__.py` (re-exports the function) + `api/skills/<name>/skill.py` (implementation) + optional `api/skills/<name>/prompt.txt` (system prompt for LLM skills).
- `__init__.py` shape:
  ```python
  from api.skills.<name>.skill import <name>
  __all__ = ["<name>"]
  ```
- **Function-based, not class-based.** No `XSkill` class — just an async function.
- **LLM skills** signature: `async def name(payload: dict[str, Any], *, llm: LLM) -> tuple[dict[str, Any], LLMMetrics]`. They return a `(dict, metrics)` tuple.
- **Non-LLM skills** signature: `async def name(payload: dict[str, Any], *, ...kwargs) -> dict[str, Any]`. They return just `dict`.
- **Sync deterministic skills** (rank_opportunities only): `def name(payload: dict) -> dict`. Hermes runner will wrap in `asyncio.to_thread`.

### LLM client (api/llm.py)
- Class is named `LLM`, NOT `LLMClient`. Import as `from api.llm import LLM, LLMMetrics`.
- Method is `complete_structured(system=..., user=..., output_model=...)`. NOT `generate_structured`.
- `output_model` MUST be a Pydantic `BaseModel` subclass — NOT a raw JSON Schema dict. Define `_FooOutput(BaseModel)` in your skill module (prefixed `_` to keep private).
- It returns `(pydantic_instance, metrics)`. Call `.model_dump()` on the instance to get a plain dict before further work.
- `LLMMetrics` fields: `model`, `latency_ms`, `cost_usd`, `input_tokens`, `output_tokens`, `cache_read_tokens`, `cache_creation_tokens`, `attempts` (`attempts=0` is valid for short-circuit no-LLM paths; use this in helpers like `_zero_metrics()`).

### Tests
- `pyproject.toml` sets `asyncio_mode = "auto"`. **Do NOT add `@pytest.mark.asyncio` decorators** — async test functions are picked up automatically.
- FakeLLM is at `api/tests/fakes.py`. Constructor kwargs: `payload: dict | None = None` (canned response) and `should_not_be_called: bool = False` (raises `AssertionError` if `complete_structured` invoked). Tracks `call_count`.
- Test fixtures `db_session` and `client` are NOT in a `conftest.py` — they're defined inline in `test_routes.py` and `test_models.py`. Copy from there or define your own.
- Always run the full suite at the end of each task: `uv run pytest -q api/tests 2>&1 | tail -3`.

### TDD with xfail-strict pattern (used for tests-first tasks like T2.1, T2.3, T2.5)
When a test-writing task lands BEFORE the implementation:
1. Write the tests with `@pytest.mark.xfail(reason="implementation pending in TX.Y", strict=True)` on every async test function.
2. Stub the skill with a function that raises `NotImplementedError`.
3. Suite stays green: `N passed, M xfailed`.
4. Implementation task removes the `xfail` decorators when impl is correct (otherwise XPASS-strict fails the suite — desired tripwire).

### Repository pattern (api/repositories/*)
- Each method auto-commits (`add → flush → commit → refresh`). DO NOT change this in any task except T7.1, which will refactor commit boundaries.
- Class names end in `Repository` (e.g., `OpportunityRepository`), NOT `Repo` (the plan sometimes says `Repo`; the actual code says `Repository`).

### Pydantic create-schemas
- `api/schemas/<name>_create.py` for input bodies. Drop `id`, `created_at`, `updated_at` (auto-managed). For nested-resource POSTs (e.g., `POST /opportunities/{id}/requirements`), also drop the URL-derived parent FK from the body.
- Use `Field(default_factory=list)` not `list[X] | None = None` for required list fields with empty default.
- Use `bool = False` not `bool | None = False` for non-nullable booleans.
- Apply `model_dump(exclude_none=True)` consistently across all 4 POST handlers (T0.1 fix-up).

### Fixtures (`fixtures/<slug>/`)
- Each fixture: `manifest.json` + `build_pdf.py` + `attachments/<filename>.pdf`.
- Manifest validates against `schemas/fixture-manifest.schema.json` via `make fixtures-validate`.
- ReportLab PDFs MUST set `invariant=1` on `SimpleDocTemplate` AND on `Canvas` (canvas-based image PDFs) for byte-deterministic regeneration. Without this, regenerating produces stale git diffs.
- Top-level manifest `slug` (kebab-case) ≠ inner `opportunity.slug` (often the solicitation_number normalized). The skill `load_seeded_opportunities` overrides with the top-level slug.
- Required `Opportunity` fields the manifest must include (beyond what the plan listed): `id`, `slug`, `resource_links`, `opportunity_status`, `created_at`, `updated_at`. Use UUID v4 for id, kebab-case for slug, `[]` for resource_links, `"open"` for opportunity_status, ISO date strings anchored to a fixed past date.
- The `slug` column on `opportunities` is NOT unique-indexed at the DB level — `get_by_slug` defensively uses `.limit(1)`.

### Date/time coercion
- asyncpg does NOT auto-coerce ISO date strings to `datetime.date` objects. When a manifest has `"due_date": "2026-06-15"`, `load_seeded_opportunities` must call `date.fromisoformat()` on `due_date` and `posted_date` fields before passing the dict to the ORM. Pattern: define a `_DATE_FIELDS = {"due_date", "posted_date"}` set and iterate.
